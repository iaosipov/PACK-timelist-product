# Failure Modes — TimeList Product

---

## What is a Failure Mode

Per SPF: a **failure mode** is a typical error when applying methods in this domain. It is not a code bug, not a random mistake, and not a personal fault.

## Detailed Failure Mode Cards

### TL.FM.001 — Неверная идентификация спикеров

**Error**: Система неправильно распределяет реплики между участниками.

**Cause**:
- TrueConf без активных окон.
- Плохое качество аудио.
- Несколько человек говорят одновременно.

**Effect**: Протокол приходится допиливать руками; снижается доверие.

**Antidote**:
- Честно предупреждать о погрешности.
- Использовать ВКС с активными окнами (Evo).
- Вести культуру говорить по очереди.
- Ручная корректировка спикеров.

**Related methods**: TL.M.004, TL.M.007

**Source**: `DS-strategy/exocortex/reference_timelist_sales.md` + `transcripts/2026-06-08/1324-...txt` + `transcripts/2026-07-31/0900-softline-timelist.txt`

### TL.FM.002 — Непредсказуемый захват задач из протокола

**Error**: TimeList выхватывает задачи непредсказуемо — упускает или создаёт лишние.

**Cause**:
- Качество аудио.
- Нечёткая формулировка поручений.
- Отсутствие единого стандарта.

**Effect**: Менеджер тратит время на ручную доработку протокола.

**Antidote**:
- Проводить встречи с чёткой культурой постановки задач.
- Дорабатывать автопротокол вручную.
- Обучать «Организатора совещаний».

**Related methods**: TL.M.004, TL.M.005

**Source**: `transcripts/2026-07-31/0900-softline-timelist.txt`

### TL.FM.003 — Дублирование систем контроля задач

**Error**: Задачи одновременно ведутся в MAX и Bitrix24, сотрудники не понимают, где им контролировать.

**Cause**:
- Резкое внедрение новой системы поверх привычного чата без интеграции.

**Effect**: Задачи теряются, снижается дисциплина, руководитель возвращается к ручному «пинанию».

**Antidote**:
- Подключить бота, который транслирует задачи из MAX в Bitrix24.
- Не ломать привычки, а надстроить отчётность.

**Related methods**: TL.M.006

**Source**: `lespromhoz-timelist.md`

---

### TL.FM.004 — Слишком много новых сущностей одновременно

**Error**: На одном пилоте запускают TimeList, Bitrix24 и ботов, сотрудники перегружены.

**Cause**:
- Отсутствие приоритизации.
- Не выбрана одна главная боль.

**Effect**: Ничего не приживается, пилот провален.

**Antidote**:
- Сначала выстроить контроль поручений в Bitrix24.
- TimeList и боты — бонус/исследовательский блок на ограниченной зоне.

**Related methods**: TL.M.006

**Source**: `lespromhoz-timelist.md`

---

### TL.FM.005 — Передача данных в зарубежный сервис

**Error**: Сотрудники используют ChatGPT/зарубежные сервисы для расшифровки совещаний.

**Cause**:
- Незнание 152-ФЗ и рисков.
- Отсутствие корпоративного инструмента.

**Effect**: Штрафы до 6 млн руб.; утечка персональных/коммерческих данных.

**Antidote**:
- Использовать TimeList/отечественные решения в закрытом контуре.
- Включить в обучение блок ИБ.

**Related methods**: TL.M.003, TL.M.007

**Source**: `transcripts/2026-06-08/1324-...txt`

---

### TL.FM.006 — Продвижение «не тому ЛПР»

**Error**: В корпоративном продукте пытаться продавать только на личной боли высшего руководителя.

**Cause**:
- Не учтено, что ЛПР в корпоративном продукте может быть ниже уровнем.

**Effect**: Посыл не резонирует, статья/предложение не заходит.

**Antidote**:
- Позиционировать через бизнес-процесс и интересы участников.
- Боль оставить частью, не основой.

**Related methods**: TL.M.002, TL.M.009

**Source**: `transcripts/2026-06-23/1307-...txt`

---

### TL.FM.007 — Конкуренция со встроенными стенограммами ВКС

**Error**: Заказчик сравнивает TimeList с бесплатными/встроенными стенограммами (Контур.Толк, Телемост, Дион) и не видит разницы.

**Cause**:
- Не продемонстрировано качество и специализация под совещания.

**Effect**: Выбор более дешёвого встроенного решения.

**Antidote**:
- Демо на реальном совещании.
- Подчёркивать точность, постобработку, кастомные термины, экспорт задач, безопасность.

**Related methods**: TL.M.001, TL.M.003

**Source**: `transcripts/2026-07-31/0900-softline-timelist.txt`
