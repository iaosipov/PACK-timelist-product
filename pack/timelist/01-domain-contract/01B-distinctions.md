## TL.D.001 — NoTaker AI vs универсальный ИИ-чат

**Definition**: TimeList — система класса NoTaker AI: специализированный агент, который из видеоконференций и офлайн-совещаний делает расшифровку, базу знаний встреч, автопротоколы и ответы на вопросы по конкретной встрече.

**Contrast with**: Универсальный генеративный чат (ChatGPT и т.п.), который не специализирован на совещаниях и не ведёт базу знаний встреч.

| NoTaker AI (TimeList) | vs. | Универсальный ИИ-чат |
|--------------|-----|--------------|
| Специализирован на совещаниях | | Универсален |
| Ведёт базу знаний встреч | | Нет персистентной базы по встречам |
| Делает автопротоколы | | Требует ручного промпта на каждый запрос |
| Работает в закрытом контуре | | Часто зарубежный сервис |

**Why it matters**: Позволяет позиционировать TimeList не как «ещё один ИИ-чат», а как специализированный инструмент для управленческой работы.

**Related items**:
- Methods: TL.M.001, TL.M.002
- Work Products: TL.WP.001, TL.WP.002

**SoTA**: `current`
- Revision criterion: Появление у конкурента аналогичной персистентной базы встреч с автопротоколами.

## TL.D.002 — Облако vs On-premise

**Definition**: Два режима развёртывания TimeList: облачный (почасовая/годовая оплата, без оборудования) и on-premise (свои серверы с GPU, выше безопасность, дороже внедрение).

**Contrast with**: Единый режим «как у всех».

| Облако | vs. | On-premise |
|--------|-----|------------|
| ~100 руб/час | | Пилот от 280 тыс./мес |
| Без оборудования | | Минимум 2 GPU по 16GB VRAM |
| Быстрый старт | | Длинный цикл закупки и настройки |
| Подходит для теста | | Нужно для госкорпораций / 152-ФЗ |

**Why it matters**: Выбор режима определяет цикл продажи, ценообразование и аргументы безопасности.

**Related items**:
- Entities: TL.ENT.011
- Failure Modes: TL.FM.005

**SoTA**: `current`
- Revision criterion: Изменение цен или появление новых конфигураций оборудования.

## TL.D.003 — Автопротокол vs стенограмма

**Definition**: Стенограмма — дословная расшифровка; протокол — структурированный результат с резюме/поручениями. TimeList умеет выдавать оба формата.

**Contrast with**: Идентификация «протокол = стенограмма».

| Стенограмма | vs. | Автопротокол |
|-------------|-----|--------------|
| Дословный текст | | Структура: решения, задачи, сроки |
| Разбивка по спикерам | | Ответственные и дедлайны |
| Используется для точности | | Используется для контроля поручений |

**Why it matters**: Клиенты покупают не текст, а управленческий результат — протокол с задачами.

**Related items**:
- Work Products: TL.WP.001, TL.WP.002
- Methods: TL.M.004, TL.M.005

**SoTA**: `current`
- Revision criterion: Изменение форматов выдачи TimeList.

## TL.D.004 — Live-бот в ВКС vs загрузка готовой записи

**Definition**: Два канала захвата аудио: пригласить бота на текущую видеовстречу (живой режим) либо загрузить готовый файл/записать через диктофон/спикерфон.

**Contrast with**: Только один способ записи.

| Live-бот | vs. | Загрузка записи |
|----------|-----|-----------------|
| Работает в ВКС (GT, TrueConf, Телемост) | | Подходит для офлайн-встреч |
| Демо в реальном времени | | До 6ч / 3ГБ |
| Нужен доступ в ВКС | | Можно через браузерное расширение |

**Why it matters**: Расширяет сценарии использования и позволяет закрывать возражение «а у нас офлайн-совещания».

**Related items**:
- Entities: TL.ENT.004
- Methods: TL.M.001, TL.M.004

**SoTA**: `current`
- Revision criterion: Изменение списка поддерживаемых ВКС или появление новых каналов захвата.

## TL.D.005 — Корпоративный таймбот vs задачник-ассистент

**Definition**: Корпоративный таймбот — бот в мессенджерах (Битрикс/Telegram/MAX), собирающий задачи из переписки. Задачник-ассистент — отдельный прототип голосового ввода задач на базе TimeList + DeepSeek.

**Contrast with**: «Таймбот = задачник-ассистент».

| Корпоративный таймбот | vs. | Задачник-ассистент |
|-----------------------|-----|--------------------|
| Бот в чатах | | Голосовой ввод |
| Собирает задачи из переписки | | TimeList + DeepSeek → Google Sheets |
| Продукт сформирован для продвижения | | Прототип, «не сформирован как продукт» |

**Why it matters**: Важно не смешивать два продукта в маркетинге и продажах.

**Related items**:
- Entities: TL.ENT.009, TL.ENT.010
- Work Products: TL.WP.007, TL.WP.008

**SoTA**: `current`
- Revision criterion: Задачник-ассистент выходит как самостоятельный продукт.

## TL.D.006 — Закрытый российский контур vs зарубежные сервисы

**Definition**: Для российских юридических лиц передача аудио в ChatGPT/зарубежные сервисы запрещена (152-ФЗ, штраф до 6 млн). TimeList работает в закрытом контуре: российские серверы, реестр отечественного ПО, on-premise.

**Contrast with**: Использование зарубежных LLM-сервисов для расшифровки.

| TimeList | vs. | ChatGPT / зарубежные сервисы |
|----------|-----|------------------------------|
| Российские серверы | | Иностранные серверы |
| В реестре отечественного ПО | | Нет |
| On-premise опция | | Нет |
| Соответствует 152-ФЗ | | Риск штрафа |

**Why it matters**: Сильнейший юридический и безопасностный аргумент в B2B-продажах.

**Related items**:
- Methods: TL.M.003
- Failure Modes: TL.FM.005

**SoTA**: `current`
- Revision criterion: Изменение законодательства или реестрового статуса.

## TL.D.007 — «Боль» vs «бизнес-процесс» в позиционировании

**Definition**: Для корпоративных продуктов эффективнее акцент не на личной боли высшего руководителя, а на улучшении бизнес-процесса и интересах участников.

**Contrast with**: Продажа собственнику через личную боль/неудовлетворённость.

| Корпоративный продукт | vs. | Продажа собственнику |
|-----------------------|-----|----------------------|
| Акцент на процессе | | Акцент на личной боли |
| ЛПР может быть ниже уровнем | | ЛПР — собственник |
| Интересы участников важны | | Решение принимает один человек |

**Why it matters**: Определяет структуру лендо-статьи и демо-скрипта.

**Related items**:
- Methods: TL.M.009
- Work Products: TL.WP.007
- Failure Modes: TL.FM.006

**SoTA**: `current`
- Revision criterion: Появление убедительных данных, что чистая боль лучше заходит в корпоративном сегменте.

## TL.D.008 — Специализация под совещания vs универсальные LLM-продукты

**Definition**: Даже если у заказчика есть собственные LLM-разработки, TimeList сохраняет позицию специализированного инструмента для совещаний, а не универсального ассистента.

**Contrast with**: Универсальный ассистент вроде будущего ассистента Битрикс24.

| TimeList | vs. | Универсальный ассистент |
|----------|-----|-------------------------|
| Заточен под совещания | | Универсален |
| Кроссплатформенность (не привязан к ВКС) | | Привязан к платформе |
| База знаний встреч | | Нет специализации |

**Why it matters**: Отвечает на возражение «а у нас уже есть LLM / скоро будет в Битриксе».

**Related items**:
- Methods: TL.M.001, TL.M.003
- Failure Modes: TL.FM.007

**SoTA**: `current`
- Revision criterion: Появление кроссплатформенного специализированного конкурента.

## TL.D.009 — Активный участник vs пассивный участник встречи

**Definition**: Активный участник ведёт обсуждение; пассивный получает индивидуальное резюме под свою зону ответственности без необходимости присутствовать лично.

**Contrast with**: «Участник = все одинаково присутствуют и слушают».

| Активный участник | vs. | Пассивный участник |
|-------------------|-----|--------------------|
| Ведёт обсуждение | | Не присутствует лично |
| Делает решения | | Читает индивидуальное резюме |
| Нужен на встрече | | Может не участвовать |

**Why it matters**: Пассивные участники — отдельная целевая аудитория и аргумент экономии времени руководителей.

**Related items**:
- Roles: TL.R.002, TL.R.003
- Work Products: TL.WP.002

**SoTA**: `current`
- Revision criterion: Изменение функционала персонализированных резюме.

## TL.D.010 — Пилотный проект vs полноценное внедрение

**Definition**: Пилот TimeList/Битрикс/ботов — ограниченный по срокам (3 недели) и кругу лиц (6 человек) тест, цель которого — выявить требования и показать работающий процесс перед масштабированием.

**Contrast with**: Сразу полноценное внедрение на всю компанию.

| Пилот | vs. | Полноценное внедрение |
|-------|-----|-----------------------|
| 3 недели | | Без ограничения по сроку |
| 6 человек | | Вся компания |
| Цель — выявить требования | | Цель — полное покрытие |
| Ограниченный бюджет | | Полный бюджет |

**Why it matters**: Снижает барьер для первой сделки и позволяет адаптировать продукт под реальные процессы клиента.

**Related items**:
- Methods: TL.M.006
- Work Products: TL.WP.005, TL.WP.006

**SoTA**: `current`
- Revision criterion: Появление стабильного шаблона пилота другой длительности/объёма.
