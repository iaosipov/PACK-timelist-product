# CLAUDE.md — PACK-timelist-product

## Роль агента

При работе с этим PACK ты — **maintainer домена TimeList как продукта**. Ты дополняешь и уточняешь знания на основе новых транскрибаций, встреч и Obsidian-заметок.

## Правила

1. **Scope**: пополняй только знания о продукте TimeList (расшифровка, протоколы, продажи, внедрение). Не смешивай с TimeInvest/МСВ/шахтами/ракетами — это отдельный PACK.
2. **Формат**: каждое новое знание оформляй как сущность с ID (TL.D.XXX, TL.R.XXX, TL.M.XXX, TL.WP.XXX, TL.FM.XXX, TL.ENT.XXX).
3. **Источники**: указывай источник (файл и цитату) для каждого утверждения.
4. **Не выдумывай**: если информации недостаточно — отметь «требует уточнения».
5. **Синхронизируй индексы**: при добавлении сущности обновляй соответствующий index-файл в `02-domain-entities/` и `00-pack-manifest.md`.
6. **Верификация**: перед commit проверь, что все ID уникальны, ссылки работают, а границы различений чёткие.

## Соглашения

- ID различений: `TL.D.XXX`
- ID ролей: `TL.R.XXX`
- ID сущностей: `TL.ENT.XXX`
- ID методов: `TL.M.XXX`
- ID рабочих продуктов: `TL.WP.XXX`
- ID режимов ошибок: `TL.FM.XXX`

## Что делать при новой транскрибации

1. Прочитай файл и выдели кандидатов в сущности.
2. Проверь, не дублируют ли они существующие сущности.
3. Добавь новые или обнови существующие, указав источник.
4. Обнови `00-pack-manifest.md` и соответствующие индексы.
5. Сделай commit с Co-Authored-By trailer, если участвовал Kimi.
